The PrimeBookOne repository is a static site — but without the access patterns, the researcher must guess: REST API or raw URLs? How to list all tiles? How to batch download 189 tiles without 429 errors? How to re-download only changed tiles? ## Paragraph 5: The Key's Teeth — Zero-Parameter Fetch

The key's teeth are cut by GitHub's platform constraints and the PrimeBookOne archive structure itself. REST API list endpoint: `GET /repos/PrimeBookOne/PrimeBookOne.github.io/contents/primebookone/0.0` returns JSON with `name`, `download_url`, `size` for all 189 tiles — exact metadata for programmatic navigation. Raw URL pattern: `https://github.com/PrimeBookOne/PrimeBookOne.github.io/raw/main/primebookone/{dir}/Tile{XX}.zip` — direct, cacheable, version-pinned, no API limits, no auth. Batch script iterates `{00..188}` with `sleep 0.1` — 189 requests, ~19 seconds per directory, ~2 minutes for all 6 directories, zero rate limit risk. Conditional download: `curl -z` with ETag/Last-Modified — archive is immutable so subsequent runs return 304 Not Modified instantly. Rate limit guidance: REST API 5000/hr (authenticated) or 60/hr (unauthenticated); raw URLs no strict limit — use raw URLs for bulk, REST only for listing. Every access pattern is determined by GitHub's published limits and the archive's static structure — zero free parameters, zero editorial choices. The key is cut from the lock's own metal.
