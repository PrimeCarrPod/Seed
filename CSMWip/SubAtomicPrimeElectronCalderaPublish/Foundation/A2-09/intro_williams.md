## Paragraph 1: The Governing Constraint

The API access patterns for fetching PrimeBookOne tiles from GitHub are not a developer guide — they are a **constraint imposed by the worldline's own publication protocol**. The constraint system is threefold: (1) the access must work within GitHub's actual rate limits (5000 req/hour authenticated, 60 req/hour unauthenticated for REST API; no strict limit for raw URLs), (2) the access must preserve the immutable, read-only nature of the worldline archive — the logbook cannot be modified by the reader, and (3) the access must be deterministic and cacheable — the same tile request must always return the same 500 gaps. The documented patterns — GitHub REST API for listing (`GET /repos/PrimeBookOne/PrimeBookOne.github.io/contents/primebookone/0.0`), raw URL access for downloading (`https://github.com/PrimeBookOne/PrimeBookOne.github.io/raw/main/primebookone/0.0/Tile00.zip`), batch download script with 100ms delay, conditional downloads with `curl -z` — are the **only** access methods that satisfy all three constraints. The raw URL pattern is not a convenience — it is the worldline's chosen publication protocol: the logbook is published as static files on GitHub Pages, not served by an API. The 100ms delay is not a suggestion — it is the courtesy interval that keeps the worldline's public archive accessible to all observers. The conditional download (`curl -z` with ETag/Last-Modified) is not an optimization — it is the protocol for respecting the archive's immutability: if the tile hasn't changed, don't fetch it again. Every subsequent paper in the 360-file program that fetches PrimeBookOne data depends on these access patterns; if the patterns violate the constraints, the archive becomes inaccessible or corrupted.

## Paragraph 2: Resolution Without Reduction

The entire API access specification — REST endpoints, raw URL patterns, batch script, rate limiting considerations, conditional downloads — resolves into the PrimeBookOne publication structure without reduction. The REST API list endpoint returns a JSON array with `name`, `download_url`, `size` for each tile — exactly the metadata needed to navigate the archive programmatically. The raw URL pattern `{base}/{dir}/Tile{XX}.zip` with base `https://github.com/PrimeBookOne/PrimeBookOne.github.io/raw/main/primebookone/` gives direct, cacheable, version-pinned access to every tile — no API rate limits, no authentication, no query parameters. The batch script `download_dir.sh` iterates `{00..188}` with 100ms delay — exactly 189 requests per directory, ~19 seconds per directory, ~2 minutes for all 6 directories, well within GitHub's generous raw content policy. The conditional download with `curl -z` uses HTTP caching headers (ETag, Last-Modified) to skip unchanged tiles — the archive is immutable so this will almost always return 304 Not Modified after the first fetch. The rate limiting guidance (5000/hr authenticated REST, 60/hr unauthenticated REST, no strict raw limit) is accurate to GitHub's published limits. This piece (08 of ~12) completes the access protocol specification; subsequent pieces will cover data validation, checksum verification, and local cache management. Zero free parameters — the GitHub platform constraints and archive structure dictate every access pattern.
