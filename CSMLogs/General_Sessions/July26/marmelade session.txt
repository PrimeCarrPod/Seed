Bounce v1.0.5 on main (4b91cf1d). MD5: 0bd2145b all 3 identical.

Broadcast Implementation: Wi-Fi Direct Bonjour
What I went with: WifiP2pManager.addLocalService() with DNS-SD Bonjour service advertising (_bounce._tcp). The TAF SSID code is published as the service instance name, with TXT records: taf=<code>, v=1.0.5, app=Bounce.

Why this approach:

Option	Feasibility	Coexists with Scan?
Wi-Fi Direct Bonjour ✅	Works API 16+, no root	Yes — separate P2P channel
Wi-Fi Direct custom SSID	Requires android.permission.NETWORK_SETTINGS (system-only)	Often interrupts normal Wi-Fi
Wi-Fi Aware (NAN)	API 26+, limited device support	Yes by design
Bluetooth LE Advertising	Works everywhere, no permissions needed	Yes
setWifiApEnabled()	Deprecated, needs WRITE_SECURE_SETTINGS (root)	No — becomes hotspot
Raw SSID manipulation	Requires rooted device, custom firmware	No
How It Works
BROADCAST button tapped
  → JS: BounceBridge.startBroadcast("TAF090/CIV065-CARORA")
  → Java: p2pManager.addLocalService(channel, bonjourServiceInfo)
  → Android: publishes "_bounce._tcp" Bonjour service
  → Other devices: can discover via Wi-Fi Direct service discovery
  → Status: "ON · P2P TX" with green pulse indicator

Scanning continues UNINTERRUPTED because:
  - Wi-Fi scanning uses WLAN interface (wlan0)
  - P2P uses P2P interface (p2p0)
  - They operate on different virtual interfaces
Graceful Degradation
If the device doesn't support Wi-Fi Direct: shows TX N/A with red indicator, Toast "Broadcast failed: P2P_UNSUPPORTED". Scanning still works fully.

Bounce v1.0.44 on main (db38011b). MD5: 3796a14a.

Permission Dialog Fix
Root cause: Normal permissions (ACCESS_WIFI_STATE, CHANGE_WIFI_STATE, NEARBY_WIFI_DEVICES, ACCESS_NETWORK_STATE) are auto-granted at install time — they never trigger a user dialog. Only "dangerous" permissions show the system prompt. By including normal perms in the request array, Android may silently handle them without showing the dialog.

Fix: Only request dangerous permissions (always triggers the system dialog):

API 29+: ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION, ACCESS_BACKGROUND_LOCATION
API <29: ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION
Added shouldShowRequestPermissionRationale() — if the user previously denied, shows a toast explaining why Bounce needs these permissions before re-requesting.

Bounce v1.0.46 on main (4781ce95). MD5: 004d37dd.

Permission Research Findings & Fix
3 key issues found:

ACCESS_BACKGROUND_LOCATION blocks the dialog — Android requires this to be requested SEPARATELY after ACCESS_FINE_LOCATION is granted. Including it in the same call causes the system to silently reject the request without showing any dialog.

Normal permissions dilute the dialog — Including ACCESS_WIFI_STATE, CHANGE_WIFI_STATE, and NEARBY_WIFI_DEVICES in the request array alongside dangerous permissions can cause Android to handle them silently, possibly skipping the dialog entirely.

Timing in onCreate — Some devices need the Activity fully created before showing the dialog. Added 500ms postDelayed.

Fix: Requests only ACCESS_FINE_LOCATION + ACCESS_COARSE_LOCATION (pure dangerous permissions) after a 500ms delay. The dialog should now appear on first launch.

  2. startScan(null, settings, btCallback) — start fresh session
  3. postDelayed → repeat in 10s

BT Fix — Root Cause
v1.0.65 added stopScan() + startScan() every 10 seconds. Android's BLE stack enforces a 5-scan-per-30-second throttle. Stopping and restarting every 10 seconds = 6 restarts every 30s = exceeded the limit. Android silently dropped all scans after the 5th restart.

Fix: Reverted to v1.0.49-style single startScan() with SCAN_MODE_LOW_LATENCY — starts once, runs continuously until stopped. No restart needed. The BT handler, 3D dots, and panel update interval are all preserved as they were in the working v1.0.49.

Build environment: Adoptium JDK 17, Android SDK 33, aapt2 33.0.1, d8 33.0.1, apksigner (no Gradle). Ephemeral filesystem requires re-downloading SDK per session.
Push to git@github.com:ZirconiaAegisC/CarrPod via GIT_SSL_NO_VERIFY=true git push origin HEAD:main.
App is a single full‑screen WebView loading bounce.html; all 3D, UI, and JS logic lives in that asset.
User provides feedback via issues; we fix and redeploy.
No manual text‑edit regressions: prefer Python‑based scripted edits to avoid JavaScript syntax errors.
Progress
Done
v1.0.33–v1.0.75 built, tested, and pushed.
Regressions fixed: frozen menus, no 3D, JavaScript errors (extra braces, garbage leftovers) traced to manual HTML edits; resolved by reverting to known‑good bases (v1.0.37, v1.0.55, v1.0.63) and applying minimal Python‑driven changes.
Trail recording reworked multiple times to eliminate GPU memory leak:
Removed per‑frame geometry disposal, then added decimation (every 3rd frame, 500‑point cap), then continuous recording with smooth CatmullRom curve, rebuild every 5 frames with dispose, 2000‑point cap, auto‑save every 60s (final in v1.0.62+).

Key Decisions
Use CatmullRomCurve3 for smooth trail lines and decimation + geometry disposal to prevent GPU memory exhaustion (original design crashed after ~5 minutes).
Implement dual‑mode Bluetooth scanning (BLE + Classic) as a fallback because BLE alone may not detect all devices on diverse Android hardware.
Apply Python‑based scripted edits (replacements via script) for all future changes to avoid manual text‑edit syntax errors that plagued earlier versions.
Keep build environment reproducible with explicit SDK/tool versions and signatures despite ephemeral filesystem.

Critical Context
BT scan throttling: Android limits startScan() to 5 calls per 30 seconds; v1.0.65 restart every 10s broke scanning, so reverted to single‑start style.
Screen lock mechanics: Two transparent UNLOCK buttons in top‑left/top‑right must be pressed within 500ms; overlay is transparent via CSS background: transparent.
Trail memory leak fix: Original implementation kept adding geometry without disposal, causing GPU memory leak → crash. Current version calls dispose() on old buffer geometry when rebuilding.
Build process: No Gradle; manual aapt2 link, d8, apksigner; build.sh script automates with version numbers.
